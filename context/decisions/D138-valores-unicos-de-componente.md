# D138 · Componentes · Regla de los literales `[…]`: escalas de diseño → token; geometría de un componente → se queda con comentario · Implementado

**Decisión:** un literal arbitrario de Tailwind solo vale si (a) es geometría propia de un componente —plantilla de grid (`md:grid-cols-[1fr_340px]`), alto de fila (`auto-rows-[108px]`), desplazamiento de parallax (`top-[-12%]`), porcentaje de esqueleto (`w-[70%]`), altura relativa a la letra en `em` (`min-h-[3.45em]`, `h-[2.6em]`), `min-h-[60vh]`— o (b) es una variante/selector/expresión (`data-[side=left]`, `has-[…]`, `calc(… var …)`, `color-mix`, `transition-[…]`, `rounded-[inherit]`, `size-[1em]`). Todo lo que pertenece a una escala de diseño (tamaño de letra, interlineado, `tracking`, ancho de contenedor) es token (D137), repita o no. Los de geometría que no se explican solos llevan un comentario `valor único: …` y, si se repiten en dos archivos (la proporción `1.6fr 1fr` del resumen y su esqueleto), cada uno remite al otro.
**Por qué:** convertir cada medida única en token llenaría `tokens.css` de nombres que nadie reutiliza; la regla deja un criterio comprobable con `git grep`.
**Alternativa descartada:** una variable CSS con nombre por cada valor único: añade indirección sin reutilización.
