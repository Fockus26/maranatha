# D102 · UI · Un `loading.tsx` con esqueleto propio por página del panel · Implementado

**Decisión:** Resumen, Proyectos, Pagos y Agenda tienen cada uno su `loading.tsx` (`app/dashboard/(panel)/{,proyectos,pagos,agenda}/loading.tsx`) con `DashboardShell` + `components/ui/skeletons/<Página>Skeleton.tsx`, que copia el layout real (contenedor, `maxWidth`, padding, columnas y breakpoints). Los textos fijos (títulos, subtítulos, filtros, encabezados de tarjeta) se pintan reales; solo lo que llega de datos va en gris. Se reutilizan `DashboardStatBand loading` y `DashboardTable loading`. `SkeletonFrame` pone `aria-busy`, un `role="status"` "Cargando <página>…" y apaga la animación con `prefers-reduced-motion` (CSS). Reemplaza la parte de D095 que fijaba un único esqueleto genérico (`DashboardPageSkeleton`, ahora sin uso, no se borra).
**Por qué:** César: el esqueleto único a todo el ancho no se parecía a ninguna página y el contenido saltaba al llegar.
**Alternativa descartada:** un esqueleto genérico con props de layout (obliga a describir cuatro layouts distintos en una sola API y se desfasa de las páginas); extraer también las filas de "Próximos cierres" de `page.tsx` (tocaría una página cerrada; se duplicó el patrón de 4 filas).
